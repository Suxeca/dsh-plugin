# 笔记看板：项目知识库拆节与常驻草案（只读提案）

> 本文不修改真实笔记、profile、preset、运行插件或既有用户裁决。基于只读核对 `Z3model/notes/.z3-ledger.md` 与 web profile note-board 配置；字符数按 JavaScript UTF-16 单位估计，迁移前必须用实际 `ledgerBody` 重新计数。**禁止自动改写冻结公式、适用条件和判决措辞。**

## 现状与约束

- 文件总长约 12,121 字符，8 个 `## <ID>` 节；当前前言与常驻正文约 8,609 字符，超过 `injectBudget: 6000` 软警戒线约 2,609。
- 常驻：FROZEN-1 787、FROZEN-2 1,239、FROZEN-3 2,767、VERDICT-1 3,128、RULES 479，另有前言约 199 字符；计数包括标题与拼接换行。
- 按需：TASK-1 1,550、OPEN 77；日志（不自动注入）：MUTATION-LOG 1,878。
- `FROZEN-3` 同时有冻结判据与 proxy 警告、实施说明、阶段性用户裁决、实测表；`VERDICT-1` 同一节内有 V1–V9 九个异质判决。目前 `note_board_read` 只能按一级 `## ID` 读取整节，不能精确读取单条 V。
- 当前前言说「全文每轮自动注入系统提示」；RULES 第 4、5 条仍说「整篇注入／从头截断」。这与当前软预算＋常驻/按需＋snapshot 机制冲突。只校正**插件机制描述**，勿借机更改研究判决。
- 用户目标是**可靠使用已确认知识**，而非单纯让数字 ≤6000。无需为了凑线截断公式、压缩 V9、重写科学推理，或引入向量库。

## 阶段 A：低风险拆分（建议优先试验）

1. **保持 FROZEN-1 和 FROZEN-2 原文与编号不变。**完整公式、端点权重、离散范围、符号与 DFT 归一化继续常驻。
2. **从 FROZEN-3 拆出一个仍名为 FROZEN-3 的“判据核心”**：框出的 G1 谱隔离不等式、同 j 的 Δ 定义和 proxy 限制、不得用全表间隔，以及原文后半段的“FAIL 不等于物理失败”、G2/G3/G4、ε 守卫等需要每次 Stage-1 判定都在场的裁决；逐字移用原句。原核心到「已裁决」段前约 961 字符，**但这 961 字符并不包含后半段上述关键规则，不能直接把它作为完整核心**。只有人工判定确属阶段性证据/实现路径的内容才另存 `STAGE1-DECISIONS`（或维持全节常驻）；在标题与正文标明“需要做 Stage-1 判定前必读 FROZEN-3 + STAGE1-DECISIONS”。C=-1 限制、j=4 用户裁决等不能因位于后半段就被当成低风险日志。先对照任务清单评估漏读，再决定是否移出。若无法保证，保持 FROZEN-3 全文常驻。
3. **把 VERDICT-1 按 V1–V9 拆成可单独读的条目**：例如 `VERDICT-1-V1` 到 `VERDICT-1-V9`，每条保留原本 V 序号、全文、适用条件和证据来源。给原 `VERDICT-1` 留一条人工确认的导航节（仅索引、旧编号到新编号对照）；不要让索引与正文形成两个彼此冲突的“当前判决”。拆分要核对 `z3_ledger replace/remove` 对已有 `VERDICT-1` 的引用是否会断裂，先演练写入/回滚；**拆分本身不自动降低常驻**，因为 `VERDICT*` 默认仍匹配所有新节。
4. 修正前言与 RULES 的旧注入描述，只陈述现行机制，不改“新证据才能推翻旧判决”之类的研究约束。

**阶段 A 的成本边界**：若机械地把 FROZEN-3 的「已裁决」后半段全移走，算术上可减约 1,758 字符至约 **6,850 字符**，**但这不是安全方案或预计实际结果**：该段包含 G2/G3/G4、ε 守卫和用户裁决，直接移出有漏用风险。保留这些关键句常驻后，实际节省一定小于 1,758，常驻很可能继续高于 6,850；须由人工逐句划界并用真实 `ledgerBody` 复核。阶段 A 的目标首先是可寻址和可验证，而非保证降到某个数字。

## 阶段 B：只有对照实测支持时才考虑

如果阶段 A 后仍昂贵，可试将 `VERDICT-1-V6`（约 433 字符）和 `VERDICT-1-V7`（约 544 字符）等与离散 x 网格专题相关的判决设为按需。仅按旧文字长度计算可再节省约 977 字符；**只有在机械移走全部 1,758 字符的危险假设下**才会出现约 **5,870 字符**这个示例数字，实际安全方案很可能仍超 6000。V6/V7 禁止裸和、说明 j 而非 Lz 决定 x 分辨率，漏读会直接导致物理误判。**先列为高风险候选，不建议直接切换。**如果测得任何一次 x 网格问题漏用，就保持它们常驻并接受软超预算。

实际操作不能只把新节改名：默认 `pinnedSections: ['FROZEN*','RULES','VERDICT*']` 会继续常驻所有 FROZEN/VERDICT。必须在方案批准后，明确列出要常驻的精确 ID，保留新按需节不匹配；采用本地 profile 覆盖时需要验证下次启动前配置可挂载。不要将改 profile 等同于插件热载即生效。

## 依赖与风险矩阵（人工复核点）

| 问题场景 | 必需材料 | 拆节后失误模式 |
|---|---|---|
| 定义 Φ_raw 和 Hann 窗、横向面元 | FROZEN-1 + FROZEN-2 | 窗端点半权/横向上界丢失；不得只凭摘要复述 |
| Stage-1 判定/门禁脚本 | FROZEN-2 换算 + FROZEN-3 核心 + STAGE1-DECISIONS + TASK-1（如涉及 9×6） | 用旧阈值、跨 j 比 Δ、错把 proxy 写成严格谱隙、漏 ε 守卫或 C=-1 裁决 |
| 动量分数采样与求和 | FROZEN-1/2 + VERDICT-V6/V7/V8，必要时 V9 | 将 Lz 当采样细化参数、无测度裸和、原始谱当无量纲 TMD |
| 胶子数与静止系 | FROZEN-2 + VERDICT-V2/V8/V9 | 用 j=0 定义胶子数、逐行二次归一化、把 UV 模式累积误说成 IR 发散 |
| 横向开边界与 bulk 截断 | VERDICT-V3 + OPEN O3 | 把越界零填充当物理算符、忽略 Bartlett 假窗 |

这些是**拟议读取义务**，不是现有模型会自动执行的保证。`note_board_read` 返回完整单节并标 `complete`，但当前插件不自动追依赖；若要强约束，需在真实场景验证漏读率，而非仅调整提示词。

## 极简 A/B 验收（控制 token）

不启动新记忆服务、不建向量索引、不拿大量 GPT 回合筛参数。先**离线**生成两个相同内容的测试副本，仅改 ID 与常驻配置：A=现状全常驻；B=阶段 A 拆分；真实笔记始终只读。

在新会话分别向 A/B 提交**相同的 4 个问题**（同一低成本模型、preset 和提问文本，少量重复防随机性）：
1. Φ_raw：复现易错分量（m′ 全范围、y 的 0-based 上界、Hann 双端点）。
2. Stage-1：G1 同 j 的 Δ/proxy、G2/G3/G4 与 ε 守卫，不允许把不可分辨说成物理失败。
3. x 网格：j 与 Lz 的关系、带测度求和、V8 前置系数不是已归一化物理分布。
4. 胶子数与静止系：j=0、二次单行归一化和 UV/IR 误读。

逐题记录：**实际模型请求 token（区分 input/cacheRead）、注入快照长度与是否重投、工具读取的条目 ID/`complete`/是否夹带日志、首个回答是否正确、漏读/错误次数**。只看摘要或“引用了 V 号”不算通过；复现相应公式和限定词才算。若 B 首轮漏任一冻结边界或用户裁决，即使省 token 也不切换。报告中分别列「每请求常驻节省」与「专题问题新增按需读取」，给出多少轮后才回本的观察值；字符数不是 token 数，不能用字符/4 直接估算中文和公式成本。

## 暂不做

- 不把历史运行日志自动摘要成“新事实”、不自动改 FROZEN/VERDICT。
- 不把语义向量检索作为权威来源；若日后材料跨多个文件、数量显著上升且确有漏召回证据，可让向量库**只负责发现候选 ID**，再用版本校验的精确条目读取原文。
- 不将其它插件的检索 Recall@5 或长对话 QA 成绩直接等同于你当前物理研究中的公式保真率。
