Profile · Bundle · Patch 的关系 维恩图 · 三个概念互相渗透，不是三个独立盒子

每个圆代表一个概念，圆的重叠区 = 两者/三者的共同点。真正"干活"的只有中心：启动叠加产出的插件树。
Bundle发货的包：npm 包 · 随版本升级 · 开箱即用
Profile本机清单：~/.dsh/profiles/web/ · 可换模板
Patch售后微调：按 id 定位 · 替换整个 config · last-write-wins
Profile ∩ Bundle清单引用货：profile 的 bundles 数组列出要装哪些 bundle
Bundle ∩ Patch货的内部就是补丁：bundle 的内容 = 一份 cordis.patch.yml
Profile ∩ Patch清单也有补丁：~/.dsh/cordis.patch.yml 微调清单里的行
三者交汇启动时按序叠加bundle → 用户 patch → --patch
→ 🌳 插件树（唯一产物）
Bundle 组合包 Profile 配置档 Patch 补丁

启动顺序（三者的协作方式）

空条目列表→ 按 Profile 清单应用 Bundle 1,2,3…→ Profile 的 patch→ home 级 cordis.patch.yml→ --patch overlay→ 🌳 插件树
每行只能被 patch 按 id 替换整个 config（不合并）；后写者赢。任何一行都可被再上层覆盖——这就是"配置即架构"。
